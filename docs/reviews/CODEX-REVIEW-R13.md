### R13-01 — Medium — estimated statistics still cannot prove RLS-hidden tables empty

**Verified:** catalog enumeration is broad, but each table is accepted when the migrator-visible query returns zero and `n_live_tup` is zero/missing. Only a permission error is treated as unreadable/holding. RLS commonly returns zero rows without an error. The migrator is NOBYPASSRLS; FORCE RLS tables exist. The new test demonstrates that a plain read of `code_sequence` hides its row, but deliberately waits 1.5 seconds for statistics before testing refusal. Sources: [`scripts/seed-training.ts:119`](https://github.com/aliescoobs-sudo/beton/blob/99072c0022cc272f3999ec35c946818ecc47662a/scripts/seed-training.ts#L119), [`scripts/seed-training.ts:132`](https://github.com/aliescoobs-sudo/beton/blob/99072c0022cc272f3999ec35c946818ecc47662a/scripts/seed-training.ts#L132), [`scripts/db-bootstrap.ts:92`](https://github.com/aliescoobs-sudo/beton/blob/99072c0022cc272f3999ec35c946818ecc47662a/scripts/db-bootstrap.ts#L92), [`db/migrations/0018_client.sql:9`](https://github.com/aliescoobs-sudo/beton/blob/99072c0022cc272f3999ec35c946818ecc47662a/db/migrations/0018_client.sql#L9), [`tests/training-admission.int.test.ts:145`](https://github.com/aliescoobs-sudo/beton/blob/99072c0022cc272f3999ec35c946818ecc47662a/tests/training-admission.int.test.ts#L145), [`tests/training-admission.int.test.ts:165`](https://github.com/aliescoobs-sudo/beton/blob/99072c0022cc272f3999ec35c946818ecc47662a/tests/training-admission.int.test.ts#L165).

PostgreSQL documents that these statistics lag, may reset after crash/recovery, and that `n_live_tup` is an estimate. A zero statistic is not an empty-table certificate. [PostgreSQL 17 statistics](https://www.postgresql.org/docs/17/monitoring-stats.html#MONITORING-STATS). RLS can silently hide rows even from an owner when FORCE RLS is active. [PostgreSQL row security](https://www.postgresql.org/docs/17/ddl-rowsecurity.html).

**Inference:** a table containing only RLS-hidden rows can be judged empty before statistics catch up or after they reset. Catalog coverage fixes the previous finance-table omission, but does not fulfill the broader “all state must be empty” guarantee. The demonstrated source case is a hidden sequence row; this is not proof that the current finance amount tables, which have migrator read policies, can all be hidden in the same way. No mixed-data seed was executed.

**Correction:** use exact maintenance reads that cannot be silently filtered, or explicitly refuse when RLS prevents such proof; do not rely on telemetry as authorization evidence. Keep admission and initialization isolated from concurrent writers. **Training containment:** independently establish a newly created dedicated volume with no restored/reused records. Do not treat successful admission as certification of an arbitrary existing database.

### R13-02 — Medium — success credits are not tied to their IP reservations

**Verified:** reservation inserts a false row at admission time; successful login appends a separate true row at completion time. Admission computes false count minus true count over the same moving timestamp window, with no reservation identifier joining a release to its original attempt. [`src/modules/platform-security/auth/login-guard.ts:99`](https://github.com/aliescoobs-sudo/beton/blob/99072c0022cc272f3999ec35c946818ecc47662a/src/modules/platform-security/auth/login-guard.ts#L99), [`src/modules/platform-security/auth/login-guard.ts:108`](https://github.com/aliescoobs-sudo/beton/blob/99072c0022cc272f3999ec35c946818ecc47662a/src/modules/platform-security/auth/login-guard.ts#L108), [`src/modules/platform-security/auth/login-guard.ts:122`](https://github.com/aliescoobs-sudo/beton/blob/99072c0022cc272f3999ec35c946818ecc47662a/src/modules/platform-security/auth/login-guard.ts#L122), [`src/app/api/field/login/handler.ts:51`](https://github.com/aliescoobs-sudo/beton/blob/99072c0022cc272f3999ec35c946818ecc47662a/src/app/api/field/login/handler.ts#L51).

**Inference:** when the original reservation ages out before its later success row, that success remains as a credit and can offset a different wrong attempt. Example: reserve at time A, succeed at A+delay; between A+window and A+delay+window, only the credit remains. Enough successful logins around that boundary allow more wrong attempts than the nominal IP failure budget. A longer pending request can lengthen the mismatch. This requires successful sign-ins on that IP; it does not remove the independent per-driver row lock or five-wrong-PIN lock.

The new reservation/concurrent HTTP tests cover a burst within one window, not reservation-versus-release expiry. [`tests/field-ip-throttle.int.test.ts:94`](https://github.com/aliescoobs-sudo/beton/blob/99072c0022cc272f3999ec35c946818ecc47662a/tests/field-ip-throttle.int.test.ts#L94).

**Correction:** give a reservation a unique identity and release that reservation while retaining its original window time; count unreleased reservations rather than subtracting unrelated timestamped success rows. Verify window-crossing completion. The eight-per-process cap bounds verification concurrency; it is not a request-body deadline, global edge rate limiter or guarantee against denial of service. **Training containment:** retain device binding/fresh seed PINs and supervision; accept this bounded IP-accounting/availability residual, not a weakened per-driver limit.

### R13-03 — Medium — late local I/O can escape the new epoch guard
