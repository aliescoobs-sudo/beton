## Findings

### Plant isolation and database actors

**R18-01 · High · Plan and order scope diverge at joins and write boundaries.** `0212:15–34,38–58` restricts a plan row and its driver. The privileged `plant_fill` permits attaching an A plan to a NULL-plant order, and the privileged plan guard reads the order, truck and driver before the INSERT policy can reject it (`0078:119–159`, `0119:104–141`). With app-login SQL and target IDs, manager A can attach a live NULL-plant order to an A plan, exposing its order code via `trip_timing` (`0210:285–305`). For historical mismatches, `dispatch_office` scopes by order plant and can return a B/NULL plan for an A order, including client, vehicle and BL fields. `order_timeline` likewise includes plan, event and delivery children by order ID alone (`0095:43–66`, `0094:164–191`). The plan guard's live-order and driver-status errors also distinguish some forbidden IDs from missing ones. **Fix** scope parent and child references before privileged reads or trigger diagnostics, with one denial for absent and foreign references. **Test** app-login A against real B/NULL parents, drivers and plans, with seeded mismatched historical children. Compare errors, inspect IDs and verify unchanged rows.

**R18-02 · High · Missing role can mutate another plant's trip and billing.** `attach_trip_load` (`0209:321–342`) and `confirm_trip_delivered` (`0210:83–111`) use `IF ... OR NOT (v_role IN (...) OR ...)`. On an existing trip with an unset role, the condition can be NULL. App-login SQL with a nonempty actor ID and real trip/load IDs can attach a matching load or confirm an eligible load, including in B or on a NULL-plant trip. `audit.append` requires a user ID and accepts this NULL role (`0076:20–32`). `confirm_trip_stage` and `correct_trip_stage` share the guard shape (`0210:117–142`, `0211:10–55`). Downstream constraints limit writes but still allow distinct errors or replay responses. **Fix** reject missing/invalid actors before lookup, using a positive role-and-scope predicate tested with `IS TRUE`. **Test** call each app-granted function with valid existing targets and unset/empty roles, verify uniform denial and unchanged events, gates and audit.

The direct plan, order-view, driver-affiliation and cancellation changes check out within their row boundaries. `0212:9–11` is a scope predicate with an intentionally unscoped result for actors without manager scope. Its callers still need authorization. The new and replaced business definers in 0212–0214 pin `search_path`. Replaced functions keep existing EXECUTE ACLs. New helper ACLs explicitly restrict the driver predicate and held count to app, the phone functions to auth, and the internal exception reader to its owner under the declared migration grants (`0001:4`, `0212:45–47,127–144`, `0213:34–41`, `0214:19–39`). Driver and pump operator have assignment-based scope through `ctx.driver_id()`, including assigned B/NULL rows. An unassigned job or rotation is refused by the ordinary field readers and writers (`0084:46–49,149–175,345–386`, `0209:184–196,285–290`, `0210:154–188`). A plant manager's scope comes from the stored account. The separate legacy `plant` role is intentionally global (`0082:20–21,56–79`).

### Reserved roles

**R18-03 · Medium · Admission leaves residual session and SQL paths.** `admit_no_reserved_accounts` deletes and then raises in the same transaction, so an active reserved account blocks migration while keeping its old session. Node startup and seed perform a count. The startup helper returns zero for a missing function (`0212:110–146`, `scripts/db-migrate.ts:24–30`, `src/modules/platform-security/service/reserved-admission.ts:23–35`, `src/instrumentation.ts:6–10`, `scripts/seed-training.ts:224`). If a privileged change introduces a reserved account after startup, the raw Better Auth `get-session` path checks lifetime without the KAYAS role gate (`src/app/api/auth/[...all]/route.ts:3–6`, `auth/create-auth.ts:23–28,92–112`, `auth/session-lifetime.ts:18–38`). The auth login can also retarget a session via UPDATE, which the INSERT trigger misses (`0004:102–104`). Existing active reserved identities still pass `ctx.actor_role` and some SQL readers, including the order view and invoice queue (`0082:27–48`, `0212:25–34`, `0066:5–18`). Protected KAYAS routes using `resolveAuthState` deny them. A previously linked field identity can also obtain a field cookie via its PIN after privileged role/status change because field login and session check only inspect the driver and device. Business SQL rechecks the role. Field push GET only returns a public key. **Fix** reject reserved stored roles at the database actor boundary and on session INSERT/retarget, invalidate cookies at the auth hook, commit cleanup separately from refusal and require the admission migration before serving. Require an active linked user of the matching kind in the field auth doors. **Test** both roles with a preexisting cookie, direct auth-session UPDATE, raw get-session, real SQL reads and a linked field account. Check revocation after failed admission.

### Field sessions and storage

**R18-04 · High · Revoked cookies revive when a phone is rebound.** `0213:5–30` uses driver ID, device hash and a per-row generation initialized to one. Releasing a phone stamps `revoked_at` (`0085:59–64`). Logging in on the same phone inserts a new row with the same hash (`0113:40–47`). The first new login increments back to the first old token's generation. A stolen unexpired old cookie can read the assigned day or send taps again, and can revoke the replacement session. **Fix** include the immutable device-row ID in the signed token and require it on check/close, or use an unrepeatable session identifier. **Test** save a signed cookie, release the device, rebind using the same device ID and verify the old cookie can neither read nor close the new session. Existing tests only relogin against the same row (`tests/t10c-field-revocation.int.test.ts:64–117`).

**R18-05 · Medium · Revocation leaves already admitted writes running and logout can clear a newer cookie.** `src/app/api/field/context.ts:39–47` checks a token once. `src/app/api/field/sync/route.ts:7–14` and `src/modules/field/service/field-service.ts:282–333` then accept a body and run up to 200 independent transactions. Pause after admission, revoke, then release the request: remaining taps still act as that driver. In another tab, an older logout response can delete the newly issued shared cookie even when its generation CAS returned false, because `src/app/api/field/logout/route.ts:23–31` ignores that result. Client transport tracking is per tab (`src/modules/field/ui/field-session.ts:80–82,273–302`). **Fix** check and fence the live session at mutation boundaries, and serialize cross-tab login/logout or let server revocation stand without an unconditional late cookie deletion. **Test** hold a sync mid-batch across revocation and delay an old logout response across another tab's login. Inspect later writes and the fresh cookie.

Field PIN throttling checked, no issue in the changed tests: `src/app/api/field/login/handler.ts:28–55` reserves before verification and bounds process concurrency. `tests/field-ip-throttle.int.test.ts:124–191,196–241` checks token-specific release, unknown-IP bucketing, burst limits and database counts during the held in-flight test. Effective trusted-hop and ingress configuration still need deployment evidence. Before expiry or effective revocation the cookie is bearer authentication. A stolen token can retrieve assigned contacts, addresses and job history, submit new-key taps, emergency actions and acknowledgements, and upload BL photos as the driver. The login throttle does not govern those operations. Replay keys deduplicate stored events without preventing new actions (`0209:225–236`, `0084:372–386`, `src/app/api/field/session/route.ts:55–80`, `src/app/api/field/bl-photo/route.ts:7–23`). Logout without a cookie, old tokens without a generation, and DB failure leaving logout pending are covered in `src/app/api/field/logout/route.test.ts:45–74` and `src/modules/field/service/session.test.ts`.

**R18-06 · Medium · Photo erasure can be undone or underreported.** `src/modules/field/ui/photo-queue.ts:386–419,605–632` filters tombstones by snapshot epoch. If the fallback lease expires after wipe reserves its epoch and before it commits, a migration can snapshot in that gap, pause, then copy an already erased photo because the tombstone epoch is at or before its snapshot. A later migration can also re-copy a legacy row left by a failed legacy erase. Tombstones are capped at 50 regardless of legacy state (`photo-queue.ts:259,271–305,643–660`). Separately, a blocked legacy open times out to NULL and counts as an empty list (`photo-queue.ts:132–161,174–181,560–582`). The pending erase can disappear across reload if localStorage persistence fails (`offline-store.ts:65–84`). **Fix** apply covering tombstones to every legacy copy until the source is fenced, validate the lease in each write transaction, and propagate unavailable storage as unknown with durable pending state. **Test** expire the lease after reservation, pause a newer snapshot across the erase commit, inject a failed legacy erase and blocked open, reload, and inspect both stores and the displayed count.

### Money surfaces

**R18-07 · High · Raw billing-gate writes bypass plant and confirmation rules.** `delivery_delivered` grants app SELECT/INSERT and admits mapped `plant` without a plant predicate (`0064:20–35`). Its definer trigger checks the load and event relationship but does not check plant, source, implicit stage or return confirmation (`0064:40–67`). A manager with app-login SQL can read B/NULL delivery and event references, mark an unlinked foreign load by ID, or insert a gate using a real driver unloading event before plant confirmation. The queue and invoice-line validation trust that row (`0066:14–29`, `0067:112–118,223–229`). The explicit confirmation definer also accepts an implicit finish, while the return gate requires an explicit finish (`0210:45–57,91–110`). **Fix** scope gate reads through delivery/rotation, remove direct app INSERT and use separate scoped manual and trip confirmation doors with explicit-finish checks. **Test** known B and NULL loads plus A's unconfirmed driver and implicit events. Assert raw reads/writes fail and the queue and invoice writer still reject the load.

**R18-08 · Medium · The held count still executes detail-dependent work.** `0214:9–16,23–39` clones the whole detail function and filters its returned rows after execution. The clone still joins orders/trucks/deliveries, computes volumes and runs discarded mismatch branches with per-order scans and sorting (`0210:210–248`). Callers can vary date ranges in SQL. Two ranges with the same held count can have different work based on hidden volume mismatches and order activity. The discarded integer aggregate can also throw if its sum exceeds integer range. The queue page collapses every count failure into zero (`src/app/[locale]/(protected)/invoices/queue/page.tsx:28–39`). The direct result is a scalar, carries no prices, names, IDs or observable row ordering, and the app login lacks EXECUTE on the internal reader. **Fix** count only the two held predicates over plans, events, cancellations and the billing marker. Bound the range and distinguish an unavailable count. **Test** equal held counts with varied irrelevant detail rows and large volume sums. Assert equal results, no errors and no execution of detail branches. Keep direct internal-function denial and office detail denial. `tests/trip-delivery-gate.int.test.ts:554–611` compares real counts and checks the payload, but does not cover the internal ACL, timing, valid plain-office and reserved-role callers, or NULL scope with a positive fixture in that count case.

Queue/invoice price gating checked, no issue in the ordinary queue service path beyond R18-07 and R18-08. It queries price only with `invoices.read` (`src/modules/ledger/service/invoice-queue-service.ts:33–63,77–105`), and the 0214 addition grants no invoice write capability. `e2e/invoice-queue.spec.ts:73–99` checks the blind invoice response and search. Separately, `office_sales` invoice PDF access is deliberate and tested (`tests/document-library.int.test.ts:79–123`).

### Runtime image and startup

**R18-10 · High · Compose checks and executes different arguments.** `scripts/training/dc.sh:24–32,38–56` stops scanning at the first non-dash token. A value-taking global option such as `--ansi never` hides a following `-f` before the subcommand. The wrapper runs `config --images` without the forwarded options, then passes them to Compose. An operator invoking the wrapper with an override file can run a different ops image with maintenance credentials. Existing tests only place denied flags first. **Fix** allowlist subcommands as the first argument or parse and validate every global option and value before accepting the command. Resolve app and ops individually using exactly the effective configuration that runs. **Test** a valued global option preceding an override with a different ops image, plus app/ops missing or substituted. **R18-11 · Medium · Startup lacks completed-ops evidence and seed commits can outlive the lease.** `scripts/training-up.sh:49–57` and `scripts/training/ops.sh` use ephemeral ops containers. Also, a suspended seeder can resume after takeover between `assertHeld` and credential placement or marker commit (`scripts/training-lib.ts:395–425`, `scripts/seed-training.ts:603–632`). A stale attempt can still publish credentials or commit a training marker. **Fix** persist narrow approved commit/digest/platform and actual ops image evidence per execution, and fence seed mutations at commit with non-expiring exclusion or an atomic holder check. **Test** disposable upgrade recording each completed ops image and pause a holder immediately after the last check at each publication boundary.

Artifact exclusions checked in source. `.dockerignore:5–36` excludes root operational env files, `brand-incoming`, `generated_images` and test sources, while retaining `.env.example`. The pinned tree has no tracked operational env or private-key file under the checked names.
