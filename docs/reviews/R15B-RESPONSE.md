| Finding | Status | What was done, and what remains |

| **R15B-01** named timing reconstructible via the ordinary board and `trip_started` | **Fixed** for the board, the raw steps and the oracle; **mitigated** for two secondary readers | `partner`/`support` lose `trips.read`, `trips.track`, `dispatch.read`, `dispatch.write` (`permissions.ts`, `TRACKING`), the raw-step policies (0208: `trip_event_read` is owner and the plant manager of the plant only; the support policy and the partner insert are dropped), and `trip_started` is split: the unscoped definition becomes `trip_started_internal` (not executable by the app login; only the cancellation guard uses it) and the app's `trip_started` answers `false` to everybody except owner, app_admin, the plant manager of the rotation's plant (and the legacy `plant` role). | **R15B-02** failed logout treated as finished; reload restores the session | **Mitigated** (client); server-side revocation **deferred** | A local sign-out mark (`bb_field_signed_out`) is set when the sign-out begins and cleared only when the server answers OK or a new sign-in succeeds. While it is set, a reload shows the sign-in, reads no day and retries the logout. A non-2xx, a failure and a deadline all keep the mark. Tests in `field-session.test.ts`. **Deferred:** a stateless signed cookie cannot be revoked by the server without a session table or a "signed out at" column and a new `field_session_check`; that changes the phone token model and needs its own decision. Real-browser cookie ordering across two tabs is still unverified. |
| **R15B-03** photo cutoffs not ordered across pages | **Deferred** (low) | Needs a shared transactional sequence in IndexedDB. The operating rule stays: one browser profile per identity, one tab. Documented in the training guide. |
| **R15B-04** photo put/delete reported before the transaction commits | **Fixed** | `photo-queue.ts`: a readwrite operation resolves on `transaction.oncomplete` and rejects on abort/error. A stale photo whose compensating delete fails now throws ("photo cleanup failed") instead of being swallowed. Tests: `photo-commit.test.ts` (put abort, delete abort, failed cleanup). |
| **R15B-05** reassignment can create an unrelated driver's overlap without an exception | **Fixed** (same day); midnight case **deferred** | `saveDispatchIn` now compares the double-bookings of the new plan with those of the stored plan and requires the override for every NEW one, wherever it falls (`overlapBaseline`); pre-existing ones are still reported, not refused. Test: `dispatch-serialization.int.test.ts` (the T1/T2/T3 scenario of the review). **Deferred:** rotations crossing midnight are still judged within one date; no adjacent-day lock or check. |
| **R15B-06** historical explanations readable in operational rows | **Mitigated** | The readers named by the review were partner and support, which now have no accounts and no tracking permission. `trip_plan.driver_override_reason` and `trip_plan_cancellation.reason` are not redacted in SQL; a database that held real history would need an explicit redaction or an empty-history admission. Training reset removes fictitious history. |
| **R15B-07** `log_dispatch_change` / `set_trip_estimate` do not reject a missing role | **Fixed**, and the class | Both now say `v_role IS NULL OR coalesce(v_role,'') NOT IN (...)`. Migration 0208 also rewrites, mechanically, every function of our schemas that still tested a role with a bare `NOT IN (...)` (NULL, not true, for a missing role) into `coalesce(role,'') NOT IN (...)`. A catalogue scan test fails if the bare form comes back (`roles-hardening.int.test.ts`, B2). A generic "raise when `app.role` is unset" was tried and **withdrawn**: the audit writer legitimately runs with a user and no role (`audit-chain` test). |
| **R15B-08** 1904 refusal fails open on valid XML | **Fixed** | The reader accepts any namespace prefix, either quote, spaces around `=`, numeric and hexadecimal character references and entities; any value that is not plainly `0`/`false` is refused. 13 synthetic workbook cases in `sheet-strict.test.ts` (6 were red before). |
| **R15B-09** non-unique names attach money to the wrong party | **Fixed** | `ambiguousKeys`: a name or a code shared by several records identifies none; clients, suppliers, components, recipes' components, cheques and opening balances refuse the row ("several records have this name or code: identify it by its unique code"). Tests in `import-conflict.int.test.ts`. |
| **R15B-10** file-only idempotency skips changed mappings | **Partially fixed** | The import audit record now stores the operation digest (file, mappings, opening date). The same bytes with another mapping or opening date are refused with a reason and no longer reported as "already imported". Runs recorded before this change have no digest and keep the old meaning. **Remaining:** the same operation on the same bytes still returns "already imported" without re-checking current conflicts; a separate validation-only path is not built. |
| **R15B-11** operator-confirmed opening date can differ silently from the one used | **Fixed** | A different `--opening-date` once the books are opened is refused for the whole sheet; at apply, an `ALREADY_ENTERED` answer re-reads the stored date and refuses if it is not the confirmed one. The old test that expected the silent replacement was rewritten. |
| **R15B-12** rollback inventory omits UPDATEs of existing counters | **Fixed** for what the invoking account can read | The inventory now also lists rows the run UPDATED and did not create (`code_sequence (updated)`). Test in `import-opening-rollback.int.test.ts`. **Remaining:** an app_admin does not read the counter audit rows; the owner's inventory is the complete one (the guide says so). |
| **R15B-13** epoch files deleted, so an old taker can steal a fresh seed lock (ABA) | **Fixed** | A released lock is no longer deleted: it stays as the high-water mark, marked abandoned, so the numbering never restarts and a delayed exclusive create of a reused number cannot succeed. Test in `training-lib.test.ts`. **Remaining:** decision 191's pause between `held()` and the write is still acknowledged; keep one maintenance operator. One small file (mode 0600) stays in the credentials folder per seed. |
