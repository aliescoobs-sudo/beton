## 1. The project in one paragraph
Management application for a friend's ready-mix concrete company in Tétouan (plants Tétouan = BELGO and Chefchaouen = CHAOUN; one office in Tétouan). It replaces Odoo (removed by the owner). It tracks money and materials together: clients, suppliers (cement, sand, other components), transport, fuel, what came in/out/was cancelled, cash vs cheque vs instalments, cheques due, advances, stock. The plant's own software reports what was loaded (e.g. B20) and the app deducts components by recipe. Owner has a private interface (little time, many problems); two office employees enter transactions; plants and drivers use phones. The owner wants APIs, agents and automation of routine work. Ali (builder, OBSIL MEDIA) is the owner's contact and decides everything on the build side.

## 11. Lessons and gotchas
- `pnpm` missing in a new terminal: `corepack pnpm …`. Never `claude --model sonnet.`.
- e2e: one full pass on AC power under `caffeinate -dimsu` (~35–45 min); Mac sleep on battery caused fake timeouts.
- Claude Code resumes after a network loss by itself (10 retries); say "continue" if not. Ignore "Update installed".
- SSH: "Enter passphrase for key" is the LOCAL key passphrase, not the server password. sshd takes the FIRST value it finds across drop-ins in lexical order. Always test a SECOND session before closing the first. Ubuntu 24.04 starts sshd on first connection (socket).
- **Ali's network is NAT64/DNS64: `ssh` cannot resolve `kayas.aliobsil.com`; always SSH to the IP 149.56.132.58** (browsers and curl resolve the name fine). Use `-o IdentitiesOnly=yes -o ServerAliveInterval=30 -i <key>`. Sessions drop often ("Connection reset", "Timeout, server not responding"); for a single read use a one-shot `ssh -t … 'command'` instead of a long session. A repo key with a passphrase breaks a non-interactive `git clone`: the read-only deploy key has no passphrase.
- Hidden prompts: a typo or the wrong keyboard layout gives a failed password with no visible clue; paste with the password manager's Copy button (a 401 on the new Basic password was a paste problem). When a pasted block contains `sudo`, run `sudo -v` ALONE first; never paste multi-line blocks where one command prompts for a password (the next lines become the password).
- **Which Terminal window is which:** `deploy@vps…` = VPS, `macplanet@ALI-OBSIL` = Mac. Outside checks (curl, nmap, openssl) must run from the Mac window; `$H` is not shared between windows (`H=kayas.aliobsil.com` in each new one). Ali mixed windows several times: identify them by prompt.
- GitHub Actions: the image digest is printed by the step "Digest to deploy" of the Build-and-push job; the digest under Artifacts is the build record. Copy it from the page.
- `docker login` leaves an empty `{"auths": {}}` after `docker logout`; check the file shows `"auths": {}`.
- A hardened Caddy (cap_drop ALL) cannot read a 0600 file owned by another uid; the macOS Docker Desktop rehearsal masks ownership, so permission bugs only show on a real Linux host. An atomic rewrite of a single bind-mounted file leaves the container on the old inode.
- Caddy's log does not print an "obtained certificate" line; verify with curl (no -k) and `openssl s_client`.
- Docker bypasses UFW for published ports; publish only 80/443. `sudo docker` (docker group = root-equivalent).
- bcrypt hashes contain `$`: never put them in Compose env; mount a file.
- Tests that assert a substring of a random sealed value are flaky; assert format instead.
- Rate limiting is a protection; never retry blindly (5 wrong PINs lock a driver; the app login has a per-IP limit of 20 failures per 15 min).
- Screenshots expose secrets (the OVH reset link; the fictitious staging passwords/PINs several times): warn, do not open, do not repeat; staging passwords change at each reset.
- **External port scans:** a full fast scan over a hotspot/ISP can lose replies and be answered by a middlebox (4 ms to a Canadian host is impossible). Validate a scan with a known-open port; use targeted `-T3 --reason` scans plus host-side `ss -ltn` / `verify-host`.
- **Two different logins on staging:** the browser's "Sign in" dialog is the Basic Auth; only after it comes the red KAYAS login page. Phone keyboards add capitals/spaces: paste instead of typing. Open each role in a separate private window.
- **Finance without TOTP:** a password-only account reaches `/fr/finance` and the page throws `FinanceUnavailable` (500, digest 3354622944): enrol the authenticator first (guide §13).
- **Signature checks on macOS:** `codesign -dv --verbose=2` shows `Signature=adhoc` / `TeamIdentifier=not set` for re-signed (cracked) binaries; `codesign --verify --deep --strict` shows patched bundles.
- The lead must not guess: verify in the repo through the bridge; read doc sections from the VPS before giving commands; when a plan changes, update this file.

- **Decision 231 — SMS is the primary driver channel.** Ali, 15 Nov 2026. All drivers and pump operators report stages by SMS, so no smartphone is needed; the phone PWA is deferred, not deleted. Each driver is registered with name, vehicle, plate and phone number. One receiving number; the message is a digit. Codes (pump and hauler columns to be confirmed with the plant managers): MIXER 1 start loading, 2 left loaded, 3 start unloading, 4 unloading done and returning; PUMP 1 left for site, 2 start pumping, 3 end pumping and cleaning, 4 returning; HAULER 1 start loading at the quarry, 2 left loaded, 3 start unloading at the stock, 4 done and returning; ALL: 5 emergency, 6 delay with optional minutes (`6 30`), 7 other; `0` asks for a correction. Pipeline: an Android phone with a local SIM as gateway → signed webhook → raw message stored insert-only → parse job → sender number mapped to driver and trip → stage order validated → event written through a narrow SECURITY DEFINER door by a service actor `sms_gateway` → boards. Unknown or unparseable messages go to an office inbox; the driver gets a short reply. Accepted limits: the timestamp is the receive time; the sender number is a weak identity. Drivers' numbers and timestamps are personal data (CNDP filing, drivers informed). The Basic Auth gate question for the webhook is a separate pending decision.
- **Decision 232 — GPS is optional, behind an adapter.** Ali, 15 Nov 2026. The company's GPS platform (ALLO GPS) is not linked now; KAYAS works with SMS only. A `PositionSource` adapter (latitude, longitude, speed, ignition, timestamp, unit id → vehicle) can be added later. KAYAS holds site coordinates and computes departure, arrival and ETA itself, corroborates SMS events and flags mismatches 'to confirm' (never blocks). Scenarios by the provider's answer: A API or forwarding, B trackers send to a second server (self-hosted Traccar), C SMS only with the T5 medians for ETA, D cheap Android phones as trackers. Scraping the platform's web interface is rejected. Positions of named drivers are personal data.
- **Decision 233 — Stock engine.** Ali, 15 Nov 2026. Recipes (component quantity per m³ per concrete class per plant); every load that leaves decreases the plant's stock by m³ × recipe, component by component, when the plant creates the BL (never from a driver tap); every receipt (cement, sand and gravel from the hauler truck and other suppliers, admixtures) increases it; physical counts are compared with the theoretical stock with a tolerance and an alert; reorder thresholds produce a request from the plant manager to office_purchases; fuel follows the same logic; later, actual batch weights from the plant software can be imported. The 15 Nov inventory showed most of this already exists; the gaps are count tolerance and alert, the plant manager's count right, the reorder request, hauler receipts and the import.
- **Decision 234 — Supplier-portal-inspired structure and modules.** Ali, 15 Nov 2026. From the study of the cement supplier's portal (structure only): owner home in five seconds (3 cards, red alerts only when there is a problem, monthly curve with drill-down); order statuses Created, Confirmed, In process, Delivered, Done, Cancelled; a complete BL with the client PO number mandatory; consumption view; fortnightly invoicing option; Excel and PDF export everywhere; a three-step order flow; supplier reconciliation (supplier BL, receipt, invoice, payment); numbered supplier purchase order; price-per-tonne history with a rise alert; cheque-reference uniqueness; list of authorised delivery destinations.
- **Decision 235 — Vehicle registry.** Ali, 15 Nov 2026. One registry of vehicles: kind (mixer, pump, hauler), plate, plant, assigned driver, driver phone (sealed), optional `gps_unit_id`; GPS units that are not fleet vehicles are never auto-assigned. The 13th vehicle is a hauler for sand, gravel and components to the stock, with its own driver.
- **Decision 236 — Cost and margin engine.** Ali, 15 Nov 2026. KAYAS computes, per m³ sold, cost, selling price and margin by concrete class and discharge method. Selling price grid = class × method: GOULOTTE (mixer alone, no pump) or POMPE (mixer plus pump truck; higher price per m³; pump service included; the pump truck is not invoiced on its own). Line amount = invoiced m³ × price per m³ for the method. Cost per m³ = materials (recipe dose × purchase price delivered to the plant, versioned) + delivery (diesel, driver, maintenance) + pump (POMPE only) + plant + overhead share. Three margins (materials, after delivery, full). Each BL freezes a cost snapshot. Costs and margins are visible only to owner and app_admin. The commercial class, the discharge method and the industrial recipe code are separate fields linked explicitly.
- **Decision 237 — Assumption mode.** Ali, 15 Nov 2026. Until real figures arrive, prices, costs and recipes are clearly flagged ASSUMED values (assumption set A1 in the handoff) stored as data (tables or seed), never hard-coded in logic and labelled 'assumption' in the UI and the seed; real values replace them through the app's data screens when Ali supplies them. Real recipes, invoices and prices never enter git, the Project or an external LLM; the seed uses fictitious recipes with the same structure. Gemini is not used for this research.
