## 1. The project in one paragraph
Management application for a friend's ready-mix concrete company in Tétouan (plants Tétouan = BELGO and Chefchaouen = CHAOUN; one office in Tétouan). It replaces Odoo (removed by the owner). It tracks money and materials together: clients, suppliers (cement, sand, other components), transport, fuel, what came in/out/was cancelled, cash vs cheque vs instalments, cheques due, advances, stock. The plant's own software reports what was loaded (e.g. B20) and the app deducts components by recipe. Owner has a private interface (little time, many problems); two office employees enter transactions; plants and drivers use phones. The owner wants APIs, agents and automation of routine work. Ali (builder, OBSIL MEDIA) is the owner's contact and decides everything on the build side.

## 11. Lessons and gotchas
- `pnpm` missing in a new terminal: `corepack pnpm …`. Never `claude --model sonnet.`.
- e2e: one full pass on AC power under `caffeinate -dimsu` (~35–45 min); Mac sleep on battery caused fake timeouts.
- Claude Code resumes after a network loss by itself (10 retries); say "continue" if not. Ignore "Update installed".
- SSH: "Enter passphrase for key" is the LOCAL key passphrase, not the server password. sshd takes the FIRST value it finds across drop-ins in lexical order. Always test a SECOND session before closing the first. Ubuntu 24.04 starts sshd on first connection (socket).
- **Ali's network is NAT64/DNS64: `ssh` cannot resolve `kayas.aliobsil.com`; always SSH to the IP 149.56.132.58** (browsers and curl resolve the name fine). Use `-o IdentitiesOnly=yes -o ServerAliveInterval=30 -i <key>`. Sessions drop often ("Connection reset", "Timeout, server not responding"); for a single read use a one-shot `ssh -t … 'command'` instead of a long session. A repo key with a passphrase breaks a non-interactive `git clone`: the read-only deploy key has no passphrase.
- Hidden prompts: a typo or the wrong keyboard layout gives a failed password with no visible clue; paste with the password manager's Copy button (a 401 on the new Basic password was a paste problem). When a pasted block contains `sudo`, run `sudo -v` ALONE first; never paste multi-line blocks where one command prompts for a password (the next lines become the password).
- **Which Terminal window is which:** `deploy@vps…` = VPS, `macplanet@ALI-OBSIL` = Mac. Outside checks (curl, nmap, openssl) must run from the Mac window; `$H` is not shared between windows (`H=kayas.aliobsil.com` in each new one). Ali mixed windows several times: identify them by prompt.
- GitHub Actions: the image digest is printed by the step "Digest to deploy" of the Build-and-push job; the digest under Artifacts is the build record. Copy it from the page.
- `docker login` leaves an empty `{"auths": {}}` after `docker logout`; check the file shows `"auths": {}`.
- A hardened Caddy (cap_drop ALL) cannot read a 0600 file owned by another uid; the macOS Docker Desktop rehearsal masks ownership, so permission bugs only show on a real Linux host. An atomic rewrite of a single bind-mounted file leaves the container on the old inode.
- Caddy's log does not print an "obtained certificate" line; verify with curl (no -k) and `openssl s_client`.
- Docker bypasses UFW for published ports; publish only 80/443. `sudo docker` (docker group = root-equivalent).
- bcrypt hashes contain `$`: never put them in Compose env; mount a file.
- Tests that assert a substring of a random sealed value are flaky; assert format instead.
- Rate limiting is a protection; never retry blindly (5 wrong PINs lock a driver; the app login has a per-IP limit of 20 failures per 15 min).
- Screenshots expose secrets (the OVH reset link; the fictitious staging passwords/PINs several times): warn, do not open, do not repeat; staging passwords change at each reset.
- **External port scans:** a full fast scan over a hotspot/ISP can lose replies and be answered by a middlebox (4 ms to a Canadian host is impossible). Validate a scan with a known-open port; use targeted `-T3 --reason` scans plus host-side `ss -ltn` / `verify-host`.
- **Two different logins on staging:** the browser's "Sign in" dialog is the Basic Auth; only after it comes the red KAYAS login page. Phone keyboards add capitals/spaces: paste instead of typing. Open each role in a separate private window.
- **Finance without TOTP:** a password-only account reaches `/fr/finance` and the page throws `FinanceUnavailable` (500, digest 3354622944): enrol the authenticator first (guide §13).
- **Signature checks on macOS:** `codesign -dv --verbose=2` shows `Signature=adhoc` / `TeamIdentifier=not set` for re-signed (cracked) binaries; `codesign --verify --deep --strict` shows patched bundles.
- The lead must not guess: verify in the repo through the bridge; read doc sections from the VPS before giving commands; when a plan changes, update this file.
