# Spec: `master-data`

Status: DRAFT · Depends on: `platform-security` · Shared conventions: [CAPABILITY-MAP.md](CAPABILITY-MAP.md)

## 1. Objective
The reference data every movement points to: who we sell to and buy from, what we make (concrete types and their recettes), what components cost, what we charge, and the trucks and zones that bound delivery. Entry must be light (lesson from Odoo): sensible defaults, codes generated, only what is needed (R26).

## 2. Data model

| Table | Key columns | Notes |
|---|---|---|
| `client` | id, code `CLT-nnn`, name, kind (`company`/`person`), ice (companies, optional in pilot), phone_enc, contact_name, default_zone_id, payment_terms_days (default 60, max 120 by agreement — R24), notes, status (`active`/`archived`) | No CIN (🟡 D57) |
| `client_site` | id, client_id, label, address_enc, zone_id | Delivery sites (chantiers) |
| `supplier` | id, code `FRN-nn`, name, category (`cement`/`aggregates`/`admixture`/`transport`/`fuel`/`other`), ice, phone_enc, payment_terms_days, status | |
| `component` | id, code, name_fr, name_ar, base_unit (`g`/`mL`/`L`), low_stock_threshold (base units), status | Cement, sand, gravel 8/15, gravel 15/25, water, admixture |
| `purchase_unit` | id, component_id, label (`t`, `m³`, `sac 50 kg`, `L`), factor_to_base (int) | Various units (✅ D8) |
| `concrete_type` | id, code (`B20`, `B25`…), label, status | |
| `recette` | id, concrete_type_id, version, effective_from (date), created_by | Versioned, never edited in place (🟡 A12) |
| `recette_line` | recette_id, component_id, qty_per_m3 (base units, int) | R1 |

## 3. Behaviour
- Codes are generated by the service (sequence per prefix), immutable once used.
- Archiving instead of deleting; archived entities can't be used in new documents but stay visible in history.
- Price/recette resolution: `resolveRecette(type, date)` and `resolveSellingPrice(type, client, date)` return the version with the latest `effective_from ≤ date` (client override first, then list price). Orders store the resolved ids so later versions never change past documents.
- Component cost per m³ of a type at a date = Σ recette_line.qty × (price_ht / factor_to_base) using `mulDivRound` — computed in `operations`/`rules-engine` domain, never stored as truth.
- Per-client price overrides (✅ A27) can be created only by owner/partner and require a non-empty reason; enforced in the service and by RLS/check constraint; audited like every price version.
- Duplicate guard: creating a client whose normalized name or ICE matches an existing one shows the match first.
- Forms are bilingual (fr/ar), RTL in `ar`; component names have both languages.

## 4. Permissions
Per SPEC-platform-security §4: owner/partner W; office W on clients/suppliers, R on types/prices; plant R on recette quantities (no prices), W on truck status.

## 5. Acceptance criteria
- **AC-MD-01** Creating a client needs only name + kind; code auto-generated; ICE optional; no CIN field exists anywhere in schema or UI.
- **AC-MD-02** A new recette version with `effective_from = D` leaves orders dated < D resolving to the old version; past orders keep their stored recette id.
- **AC-MD-03** `resolveSellingPrice` prefers an active client override over the list price; returns an error (not 0) when no price exists.
- **AC-MD-04** Purchase unit conversion: 2.5 t of cement at 1 450,00 MAD/t HT → 2 500 000 g, cost 3 625,00 MAD; property test: cost is integer centimes and independent of the unit used to express the same quantity within ±1 centime.
- **AC-MD-05** Archived client cannot be selected in a new order; existing orders still show it.
- **AC-MD-06** Delete is not offered in any master-data UI and the DB has no DELETE grant on these tables.
- **AC-MD-07** Plant role sees recette quantities without any price; office cannot change purchase or selling prices.
- **AC-MD-08** Truck breakdown logged by plant for [D4, D6) makes the truck unavailable in capacity checks for those dates.
- **AC-MD-09** All master-data screens render correctly in `fr` and `ar` (RTL) — Playwright screenshot check.
- **AC-MD-10** Office or plant creating a per-client price override is refused (service + RLS); owner/partner without a reason is refused; with a reason it is saved and audited.
